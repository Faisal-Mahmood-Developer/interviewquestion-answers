HTML

HTML (HyperText Markup Language) is the standard markup language for creating web pages. It describes the structure of a web page using a system of elements (tags) that are interpreted by browsers to display content. HTML provides the skeleton of a webpage, defining headings, paragraphs, links, images, and other media.

Every HTML document must have a <!DOCTYPE html> declaration and a <html> root element containing <head> and <body> sections.

<!DOCTYPE html>
                                    <html lang="en">
                                    <head>
                                    <meta charset="UTF-8">
                                    <meta name="viewport" content="width=device-width, initial-scale=1.0">
                                    <title>Page Title</title>
                                    </head>
                                    <body>
                                    <h1>Hello World</h1>
                                    <p>This is a paragraph.</p>
                                    </body>
                                    </html>
  • <!DOCTYPE html> – defines document type and HTML5 version.
  • <html> – root element.
  • <head> – contains meta‑information, title, links to stylesheets, scripts.
  • <body> – contains visible page content.

CSS

CSS (Cascading Style Sheets) is a style sheet language used to describe the presentation of a document written in HTML.

  • Separates content from presentation.
  • Improves page load speed (caching).
  • Enables responsive design.
  • Provides consistent styling across pages.
  • Offers flexibility and control over layout.

  1. Inline – using style attribute on an element.
  2. Internal – using <style> tag inside <head>.
  3. External – linking an external .css file via <link>.
<!-- Inline -->
                                        <p style="color: red;">Text</p>

                                        <!-- Internal -->
                                        <style> p { color: blue; } </style>

                                    <!-- External -->
                                    <link rel="stylesheet" href="styles.css">

Every element is represented as a rectangular box consisting of:

  • Content: The actual content (text, image, etc.).
  • Padding: Space between content and border.
  • Border: Surrounds padding (can be styled).
  • Margin: Space outside the border, separating from other elements.

Total width = width + padding + border + margin (in standard box model). With box-sizing: border-box, width includes padding and border.

box-sizing: border-box; /* includes padding and border in width/height */

Selectors target HTML elements. Specificity determines which styles apply when multiple rules conflict. Order (highest to lowest):

  1. Inline styles (style="...") – 1000
  2. IDs (#id) – 100
  3. Classes, pseudo-classes, attributes (.class, :hover, [type]) – 10
  4. Elements (div, p, h1) and pseudo-elements (::before) – 1
  5. Universal selector (*), combinators (+, >, ~) – 0

If equal specificity, the later rule wins.

  • id (#id): Must be unique within a page. Used for unique elements. Higher specificity.
  • class (.class): Can be reused on multiple elements. Lower specificity.

  • static: default; element follows normal flow.
  • relative: positioned relative to its normal position.
  • absolute: positioned relative to its nearest positioned (non-static) ancestor.
  • fixed: positioned relative to the viewport, stays fixed on scroll.
  • sticky: toggles between relative and fixed based on scroll position.
.position-example {
                                        position: relative;
                                        top: 20px;
                                        left: 10px;
                                    }

  • display: none: element is removed from the document flow; space is not occupied.
  • visibility: hidden: element is hidden but still occupies space in the layout.

  • Pseudo‑classes (:) target an element's state (e.g., :hover, :focus, :active, :nth-child()).
  • Pseudo‑elements (::) target specific parts of an element (e.g., ::before, ::after, ::first-line).
a:hover { color: red; }
                                        p::first-line { font-weight: bold; }
                                    div::before { content: "★"; }

Flexbox (Flexible Box Layout) is a one‑dimensional layout model that arranges items in rows or columns and provides space distribution.

Key properties:

  • display: flex on container.
  • flex-direction: row, row-reverse, column, column-reverse.
  • justify-content: alignment along main axis (flex-start, flex-end, center, space-between, space-around, space-evenly).
  • align-items: alignment along cross axis.
  • flex-wrap: wrap, nowrap, wrap-reverse.
  • flex (shorthand): flex-grow, flex-shrink, flex-basis.
  • order: changes order of items.
.container {
                                        display: flex;
                                        justify-content: center;
                                        align-items: center;
                                        flex-wrap: wrap;
                                    }
                                    .item {
                                        flex: 1 0 200px; /* grow, shrink, basis */
                                    }

z-index controls the stacking order of positioned elements (non‑static). Higher values appear on top. It only works on positioned (relative, absolute, fixed, sticky) elements. Default stacking order is by source order.

JavaScript is a high-level, interpreted, dynamically typed, multi-paradigm programming language primarily used for creating interactive web pages. It conforms to the ECMAScript specification.

  • Lightweight & Interpreted: Executed directly in the browser or server (Node.js).
  • Dynamic Typing: Variables can hold any type without declaration.
  • First-Class Functions: Functions are treated as objects and can be assigned to variables, passed as arguments, and returned.
  • Prototype-Based Inheritance: Uses prototypes rather than classical classes (though ES6 adds class syntax).
  • Event-Driven & Asynchronous: Utilizes an event loop for non-blocking I/O.
  • Single-Threaded: Uses a single main thread for execution, managed by the event loop.

Hoisting is a behavior where variable and function declarations are moved to the top of their scope during the compilation phase.

  • var variables are hoisted and initialized with undefined.
  • let and const are hoisted but remain in a "Temporal Dead Zone" (TDZ) until declaration, throwing ReferenceError if accessed early.
  • Function declarations are fully hoisted (can be called before declaration).
console.log(hoistedVar); // undefined (hoisted)

                                        greetExpr(); // TypeError

A closure is a function that remembers its lexical scope even when the function is executed outside that scope. It allows inner functions to access variables from outer (enclosing) functions even after the outer function has returned.

In JavaScript, objects can inherit properties and methods from other objects via the prototype chain. Every object has an internal [[Prototype]] link (accessible via __proto__ or Object.getPrototypeOf()). When accessing a property, JS looks at the object itself, and if not found, traverses the prototype chain.

                                        this.name = name;
                                        }

                                        const dog = new Animal('Rex');
                                        dog.speak(); // Rex makes a sound

                                        class Dog extends Animal {
                                        speak() {
                                        console.log(`${this.name} barks`);
                                        }
                                        }
                                        const rex = new Dog('Rex');
                                    rex.speak(); // Rex barks

The event loop is the mechanism that allows JavaScript (single‑threaded) to handle asynchronous operations. It continuously checks the call stack and the task queues.

  • Call Stack – Executes synchronous code.
  • Web APIs – Handles async tasks (setTimeout, fetch, events).
  • Callback Queue – Holds callbacks ready to execute.
  • Microtask Queue – Higher priority (Promises, MutationObserver, queueMicrotask).
  • Event Loop – Moves callbacks from queues to the call stack when it is empty. Microtasks are executed before macrotasks.
console.log('Start');              // 1
                                        setTimeout(() => console.log('Timeout'), 0); // 4 (macrotask)
                                        Promise.resolve().then(() => console.log('Promise')); // 3 (microtask)
                                        console.log('End');                // 2
                                    // Output: Start, End, Promise, Timeout

A Promise is an object representing the eventual completion (or failure) of an asynchronous operation. It has three states: Pending, Fulfilled (resolved), or Rejected.

const myPromise = new Promise((resolve, reject) => {
                                        const success = true;
                                        if (success) {
                                        resolve('Data loaded');
                                        } else {
                                        reject('Error occurred');
                                        }
                                        });

                                        myPromise
                                        .then(data => console.log(data))
                                        .catch(err => console.error(err))
                                        .finally(() => console.log('Done'));

                                        // Promise static methods
                                        Promise.all([promise1, promise2])   // Waits for all (rejects if any fails)
                                        Promise.allSettled([...])           // Waits for all (never rejects)
                                        Promise.race([promise1, promise2])  // Resolves/rejects with the first settled
                                    Promise.any([promise1, promise2])   // Resolves with the first fulfilled

V8 is Google's open-source JavaScript engine written in C++. It compiles JavaScript to native machine code before executing it. Features include:

The event loop is what allows Node.js to perform non-blocking I/O operations despite JavaScript being single-threaded. It works by:

  1. Executing all synchronous code first.
  2. Processing microtasks (Promise callbacks).
  3. Processing macrotasks (callbacks from I/O operations).
  4. Repeating this cycle indefinitely.
console.log('Start'); // 1st

                                        Promise.resolve().then(() => console.log('Promise')); // 3rd
                                        console.log('End'); // 2nd

The event loop has six phases:

  1. Timers: Executes setTimeout() and setInterval() callbacks.
  2. Pending Callbacks: Executes I/O-related callbacks.
  3. Idle, Prepare: Internal use only.
  4. Poll: Retrieves new I/O events and executes callbacks.
  5. Check: Executes setImmediate() callbacks.
  6. Close Callbacks: Executes close event callbacks.

  • setImmediate(): Executes in the "check" phase, immediately after the "poll" phase.
  • setTimeout(): Executes in the "timers" phase, after the specified delay.

  • Macrotasks (lower priority, executed in event loop cycles): setTimeout(), setInterval(), I/O operations, setImmediate().

SQL (Structured Query Language) is a domain-specific language used for managing and querying relational databases.

MySQL is an open-source relational database management system (RDBMS) that uses SQL. It's widely used in web applications and is known for its reliability, performance, and ease of use.

  • DDL (Data Definition Language): CREATE, ALTER, DROP, TRUNCATE – define and modify database structure.
  • DML (Data Manipulation Language): INSERT, UPDATE, DELETE, SELECT – manipulate data.
  • DCL (Data Control Language): GRANT, REVOKE – manage permissions.
  • TCL (Transaction Control Language): COMMIT, ROLLBACK, SAVEPOINT – manage transactions.

Indexes improve query performance by creating an efficient data structure for searching.

// Create a single field index
                                        await User.createIndex({ email: 1 }); // 1 = ascending, -1 = descending

                                        // Create a unique index
                                        await User.createIndex({ email: 1 }, { unique: true });

                                        // Create a compound index
                                        await User.createIndex({ name: 1, age: -1 });

                                    // Text index for full-text search
                                    await User.createIndex({ description: 'text' });

  • Embedding: Store related data within the same document. Best for one-to-one and one-to-many relationships where the child data is always accessed with the parent.
  • Referencing: Store references (ObjectId) to other documents. Best for many-to-many relationships or when data is frequently updated independently.
// Embedding
                                        {
                                        _id: 1,
                                        name: 'John',
                                        address: { street: 'Main St', city: 'NYC' }
                                        }

                                        // Referencing
                                        {
                                        _id: 1,
                                        name: 'John',
                                        addressId: ObjectId('...')
                                    }

ObjectId is a 12-byte BSON type that MongoDB uses as the default value for _id fields. It consists of:

  • 4 bytes: Timestamp (seconds since UNIX epoch).
  • 5 bytes: Random value (machine + process).
  • 3 bytes: Incrementing counter.

This ensures uniqueness and the ability to sort by creation time.

$lookup performs a left outer join with another collection. It's MongoDB's equivalent of SQL JOIN.

const usersWithOrders = await User.aggregate([

                                        from: 'orders',
                                        localField: '_id',
                                        foreignField: 'userId',
                                        as: 'orders'
                                        }
                                        }
                                    ]);

MongoDB supports multi-document ACID transactions (since version 4.0).

const session = await mongoose.startSession();
                                        session.startTransaction();

                                        try {
                                        const user = await User.findById(userId).session(session);
                                        user.balance -= amount;
                                        await user.save({ session });

                                        const order = new Order({ ... });
                                        await order.save({ session });

                                        await session.commitTransaction();
                                        } catch (error) {

  • Replication: Creates multiple copies of data across different servers (Replica Sets). Provides high availability and data redundancy.
  • Sharding: Distributes data across multiple servers (shards). Provides horizontal scalability for large datasets.

Replica Set: Primary (writes), Secondaries (read replicas), Arbiter (voting).

Sharding: Shards (data), Mongos (router), Config Servers (metadata).
